Autoryzacja w query

Brak sprawdzenia własności w odczycie to IDOR (Broken Access Control, OWASP Top 10). Query nie ma niezmienników, ale autoryzację ma zawsze.

RodzajGdzie
deklaratywna (rola, uwierzytelnienie)na trasie: .RequireAuthorization(…)
zasobowa (per instancja)w handlerze — wymaga danych
Filtruj u źródła. store.GetVisibleTo(id, user) zamiast GetById(id) + if. Zapomniany if nie wywala testu — cicho oddaje cudze dane. W EF Core: global query filter.
Zwracaj 404, nie 403, gdy zasób jest cudzy — 403 potwierdza jego istnienie.

Interfejsy

namespace Helpdesk.Common;

public interface ICommandHandler<in TCommand, TResult>
{
    Task<TResult> HandleAsync(TCommand command, CancellationToken cancellationToken = default);
}

public interface IQueryHandler<in TQuery, TResult>
{
    Task<TResult> HandleAsync(TQuery query, CancellationToken cancellationToken = default);
}

  TicketsFeature.cs   // rejestracje + mapowanie endpointów
public record CreateTicketCommand(string Title);

public class CreateTicketHandler(ITicketStore store, ICurrentUser user)
    : ICommandHandler<CreateTicketCommand, Ticket>
{
    public Task<Ticket> HandleAsync(CreateTicketCommand command, CancellationToken ct = default)
        => Task.FromResult(store.Add(command.Title));
}

Rejestracja i wywołanie

services.AddScoped<ICommandHandler<CreateTicketCommand, Ticket>, CreateTicketHandler>();

tickets.MapPost("/",
    async (CreateTicketRequest request,
           ICommandHandler<CreateTicketCommand, Ticket> handler,
           CancellationToken ct) =>
    {
        var ticket = await handler.HandleAsync(new CreateTicketCommand(request.Title), ct);
        return TypedResults.Created($"/tickets/{ticket.Id}", ticket);
    });
Handlery zawsze Scoped. Zależą od serwisów żądania (ICurrentUser, później DbContext). Singleton nie może po nie sięgać.
