curl: testowanie API z basha

Ściąga do druku. Wszystkie komendy sprawdzone w Git Bashu na Windows 11 (curl 8.16.0) przeciw projektowi Helpdesk na http://localhost:5006.

Używane w lekcji 0008.

Cztery metody

# GET
curl -s http://localhost:5006/tickets
curl -s http://localhost:5006/tickets/1

# POST
curl -s -i -X POST http://localhost:5006/tickets \
  -H "Content-Type: application/json" \
  -d '{"title":"Drukarka nie drukuje","priority":"high"}'

# PUT
curl -s -i -X PUT http://localhost:5006/tickets/1 \
  -H "Content-Type: application/json" \
  -d '{"title":"Poprawiony tytul","priority":"low"}'

# DELETE
curl -s -i -X DELETE http://localhost:5006/tickets/2

Apostrofy wokół JSON-a załatwiają wszystko: cudzysłowy w środku i spacje w wartościach. Backslash \ na końcu linii łamie długą komendę.

Jedyna pułapka: polskie znaki w argumencie

# NIE ZADZIAŁA — 500, "Cannot transcode invalid UTF-8 JSON text"
curl -X PUT http://localhost:5006/tickets/1 -H "Content-Type: application/json" \
  -d '{"title":"Poprawiony tytuł","priority":"low"}'

# ZADZIAŁA — ciało z pliku
cat > body.json <<'JSON'
{"title":"Zgłoszenie z polskimi znakami: ąćęłńóśźż","priority":"normal"}
JSON
curl -s -i -X POST http://localhost:5006/tickets -H "Content-Type: application/json" --data-binary @body.json
Git Bash przekazuje argumenty do curl.exe (programu windowsowego) przez konwersję na stronę kodową Windows — UTF-8 się po drodze psuje. Sam plik jest w porządku, bo curl czyta go bajt po bajcie. ASCII w -d, polskie znaki przez plik.

Ciało z pliku

curl -s -X POST http://localhost:5006/tickets -H "Content-Type: application/json" --data-binary @body.json
WariantRóżnica
-d @plikwycina znaki nowej linii z ciała — dla JSON-a zwykle bez znaczenia
--data-binary @plikwysyła plik bajt w bajt; bezpieczniejszy domyślny wybór
-d @-ciało ze standardowego wejścia (echo '...' | curl -d @- ...)

Przydatne flagi

FlagaZnaczenie
-X METODAmetoda HTTP; bez tego GET (albo POST, gdy jest -d)
-H "Nagłówek: wartość"nagłówek żądania
-d '...'ciało żądania
--json '...'skrót: -d + Content-Type + Accept ustawione na JSON
-inagłówki odpowiedzi razem z ciałem (widać status)

# tylko status — do szybkiego przelotu przez tabelę weryfikacyjną
curl -s -o /dev/null -w "%{http_code}\n" -X DELETE http://localhost:5006/tickets/2

# ciało, a pod nim status
curl -s -w "\n=> %{http_code}\n" http://localhost:5006/tickets/99

# krótszy POST
curl -s --json '{"title":"Zepsuta drukarka","priority":"high"}' http://localhost:5006/tickets

Nagłówki własne

curl -s http://localhost:5006/tickets -H "X-User: wojtek"
curl -s http://localhost:5006/tickets/99 -H "Accept: application/problem+json"

Cała tabela weryfikacyjna jednym plikiem

#!/bin/bash
API=http://localhost:5006

check() { curl -s -w "\n=> %{http_code}\n" "$@"; echo; }

check -X POST $API/tickets -H "Content-Type: application/json" -d '{"title":"Zepsuta drukarka","priority":"high"}'
check -X POST $API/tickets -H "Content-Type: application/json" -d '{"title":"","priority":"urgent"}'
check -X PUT  $API/tickets/1 -H "Content-Type: application/json" -d '{"title":"Poprawiony","priority":"low"}'
check -X DELETE $API/tickets/2
check -X DELETE $API/tickets/2
