Katalog błędów mieszka w feature, nie w Common/. Metoda, gdy komunikat ma parametr; static readonly pole, gdy jest stały.

Handler

public class DomainExceptionHandler(IProblemDetailsService problemDetailsService) : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(HttpContext ctx, Exception ex, CancellationToken ct)
    {
        if (ex is not DomainException domain) return false;

        ctx.Response.StatusCode = StatusFor(domain.Error.Type);

        return await problemDetailsService.TryWriteAsync(new ProblemDetailsContext
        {
            HttpContext = ctx,
            Exception = ex,
            ProblemDetails =
            {
                Title = TitleFor(domain.Error.Type),
                Detail = domain.Error.Message,
                Status = ctx.Response.StatusCode,
                Extensions = { ["code"] = domain.Error.Code }
            }
        });
    }
}
ZwrotZnaczenie
false„nie mój wyjątek" — leci do następnego handlera, na końcu do fallbacku
true„obsłużone" — musisz napisać całą odpowiedź ze statusem, inaczej klient dostanie puste 404

Rejestracja

builder.Services.AddProblemDetails();
builder.Services.AddExceptionHandler<DomainExceptionHandler>();   // Singleton!

var app = builder.Build();

app.UseExceptionHandler();   // middleware — przed MapXxx()

Handlery uruchamiają się w kolejności rejestracji. UseExceptionHandler() bez argumentu wymaga fallbacku: albo AddProblemDetails(), albo ścieżki (UseExceptionHandler("/error")), albo lambdy.

Zasady bezpieczeństwa

Klient dostaje traceId, log dostaje stack trace — nigdy odwrotnie. Developer exception page (pełny stos, ścieżki na dysku, nagłówki) działa tylko w Development i nie jest planem na produkcję.
Zasób cudzy zwracaj jako 404, nie 403 — 403 potwierdza, że zasób istnieje. Stąd ErrorType.Forbidden może mapować się na 404 (patrz ściąga CQRS, sekcja o IDOR).
