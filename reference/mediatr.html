MediatR

Ściąga do druku. Zweryfikowane na .NET 10.0.400 i MediatR 14.2.0; nazwy i zmiany wersji wg MediatR Wiki.

Ćwiczone w lekcji 0010. Poprzednik: własny dispatcher. Walidacja: FluentValidation.

Instalacja i rejestracja

dotnet add package MediatR
services.AddMediatR(configuration =>
{
    configuration.RegisterServicesFromAssemblyContaining<Program>();
    configuration.AddOpenBehavior(typeof(ValidationBehavior<,>));
});

Skan assembly rejestruje wszystkie IRequestHandler i INotificationHandler. Behaviory odpalają się w kolejności rejestracji.

Warstwa nazw nad IRequest

public interface ICommandBase;

public interface ICommand : IRequest, ICommandBase;
public interface ICommand<out TResponse> : IRequest<TResponse>, ICommandBase;
public interface IQuery<out TResponse> : IRequest<TResponse>, ICommandBase;

public interface ICommandHandler<in TCommand> : IRequestHandler<TCommand>
    where TCommand : ICommand;
public interface ICommandHandler<in TCommand, TResponse> : IRequestHandler<TCommand, TResponse>
    where TCommand : ICommand<TResponse>;
public interface IQueryHandler<in TQuery, TResponse> : IRequestHandler<TQuery, TResponse>
    where TQuery : IQuery<TResponse>;

Zero logiki. Daje: rozróżnienie command/query (MediatR go nie zna), constraint uniemożliwiający pomylenie handlerów, i marker, po którym ograniczają się behaviory.

IQuery też dziedziczy po ICommandBase — marker mimo nazwy obejmuje zapytania. Behavior z where TRequest : ICommandBase odpali się na GET. Dobre dla walidacji, złe dla transakcji i audytu.

Pipeline behavior

public class ValidationBehavior<TRequest, TResponse>(IEnumerable<IValidator<TRequest>> validators)
    : IPipelineBehavior<TRequest, TResponse>
    where TRequest : ICommandBase
{
    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        // przed
        var response = await next(cancellationToken);
        // po
        return response;
    }
}

Nie wywołasz next — łańcuch się urywa i handler nie zobaczy wiadomości. Typowe behaviory: walidacja, logowanie, pomiar czasu, transakcja, retry, cache.

Bezwynikowy request też przechodzi przez pipeline — wewnątrz biblioteki jego TResponse to Unit. Behavior odpala się normalnie (sprawdzone: PUT z pustym tytułem daje 400).
