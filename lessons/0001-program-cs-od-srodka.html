Lekcja 0001 · ~15 min · projekt Helpdesk

Program.cs od środka: builder, app, endpoint

Cel: stworzyć projekt Helpdesk, uruchomić go i umieć wytłumaczyć każdą z czterech linijek, które .NET wygenerował. Bez tego żaden DI ani CQRS nie ma sensu.

Wymaga: .NET SDK 10 (masz 10.0.400), VS Code, terminal. Zero C# — wszystko, co potrzebne, jest poniżej.

Po co ta lekcja

W firmowym backendzie Program.cs ma zwykle 100–300 linii i wygląda strasznie. Ale to zawsze ten sam szkielet w dwóch fazach: konfiguruję (przed Build()) i obsługuję żądania (po Build()). Dependency Injection, o którym jest następna lekcja, żyje w pierwszej fazie. Endpointy, handlery, walidacja — w drugiej. Jeśli widzisz tę granicę, resztę da się czytać.

Cztery linijki

Tyle generuje dotnet new web w .NET 10 (zweryfikowane na twojej maszynie):1

1Szablon web to „ASP.NET Core — puste”. Szablon webapi dodaje OpenAPI i przykładowy endpoint; celowo zaczynamy od pustego, żeby każdą linię dopisać samemu.
project/Helpdesk/Program.cs
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Hello World!");

app.Run();
LiniaCo robiAnalogia JS
CreateBuilder(args)Tworzy WebApplicationBuilder: wczytuje appsettings.json, zmienne środowiskowe, ustawia logowanie i pusty rejestr serwisów builder.Services. Nic nie nasłuchuje.Faza „importy i konfiguracja” na górze pliku Express, ale wbudowana i ustandaryzowana.
builder.Build()Zamraża rejestr serwisów i buduje WebApplication. Po tej linii nie da się już zarejestrować serwisu — to granica dwóch faz.const app = express() — z tą różnicą, że Express nie ma fazy „przed”.
app.MapGet(path, handler)Rejestruje endpoint: trasa + lambda. Zwrócony obiekt jest serializowany do JSON, string idzie jako text/plain.app.get('/', (req, res) => res.send('Hello')), tylko zwracasz wartość zamiast wołać res.send.
app.Run()Startuje serwer Kestrel i blokuje do zamknięcia procesu.app.listen(port).
W Vue masz createApp(App) → .use(router).use(pinia) → .mount('#app'). Tu jest to samo: CreateBuilder → builder.Services.Add… → Build() → Map… → Run(). Po mount nie dodasz pluginu; po Build nie dodasz serwisu.

Składnia C#, którą tu widzisz

  • var — inferencja typu jak const w TS; typ jest statyczny, nie dynamiczny.
  • () => "Hello World!" — lambda, identyczna jak arrow function.
  • Brak klasy i Main — to top-level statements; kompilator sam owija plik w metodę startową. Tylko jeden plik w projekcie może tak wyglądać.
  • Średniki są obowiązkowe. Kompilator powie, gdzie brakuje.

Pełniejsza ściąga składni: Glossary → „Składnia C# dla ludzi od TS”.

Zadanie

Zbuduj Helpdesk i dodaj pierwszy endpoint

  1. W terminalu, w C:\PLAYGROUND\asp: 
    dotnet new web -n Helpdesk -o project/Helpdesk
cd project/Helpdesk
dotnet run
    W konsoli pojawi się Now listening on: http://localhost:XXXX. Otwórz ten adres w przeglądarce. Port jest w Properties/launchSettings.json.
  2. Zatrzymaj (Ctrl+C). Uruchom ponownie przez dotnet watch run — przebudowuje po zapisie pliku, jak Vite HMR (wolniej, ale działa).
  3. Dodaj pod istniejącym MapGet drugi endpoint zwracający listę zgłoszeń. Zwróć tablicę obiektów anonimowych (new[] { new { Id = 1, Title = "…" }, … }) — bez klas, bez DTO, to przyjdzie później. Sprawdź w przeglądarce, że /tickets zwraca JSON i że nazwy pól są w camelCase mimo że w C# napisałeś PascalCase.
  4. Dodaj trzeci endpoint z parametrem trasy: /tickets/{id}. Handler przyjmuje (int id) — nazwa parametru lambdy musi zgadzać się z nazwą w klamrach. Zwróć obiekt z tym id. Wejdź na /tickets/abc i zobacz, co ASP.NET robi, gdy nie może zbindować int.
  5. Przenieś wywołanie app.MapGet("/tickets", …) przed linię var app = builder.Build();. Przeczytaj błąd kompilatora. Cofnij.
Nie kopiuj kodu z lekcji — przepisuj. Literówki i czerwone podkreślenia w VS Code to część nauki: uczysz się czytać komunikaty kompilatora C#, a one są dużo bardziej gadatliwe niż TS.

Sprawdź się

Odpowiedz zanim klikniesz. Zła odpowiedź nie zdradza dobrej — spróbuj jeszcze raz.

Po której linii nie da się już zarejestrować nowego serwisu w kontenerze DI?
Build() zamraża builder.Services i tworzy kontener. MapGet i Run są już po tej granicy.
Handler () => new { Id = 1 } zwraca do klienta:
Obiekty są serializowane do JSON, a domyślna polityka nazw to camelCase. Tylko string idzie jako zwykły tekst.
W app.MapGet("/tickets/{id}", (int id) => …) skąd handler wie, co wstawić w id?
Minimal API wiąże parametry po nazwie: {id} w trasie → parametr id. Atrybuty są opcjonalne i służą do rozstrzygania niejednoznaczności.
Jakie dwie fazy ma Program.cs i co jest granicą?

Faza konfiguracji (rejestrowanie serwisów na builder.Services, config, logowanie) i faza obsługi żądań (middleware, endpointy). Granicą jest builder.Build().

Czym różni się dotnet new web od dotnet new webapi?

web = pusty Program.cs z jednym Hello World. webapi = dodatkowo OpenAPI i przykładowy endpoint pogody. Ta sama maszyneria.
